# Email editor and default mailbox navigation — 2026-10-07

User scope: shared open-source editor for compose/signatures with image/file upload based on cloud-mail storage; open the default mailbox after login; upper-left mailbox switcher plus all-mailbox list. Preserve the existing shadcn-admin layout and concise interaction.

## Decisions and dependencies

- Evaluated Tiptap (MIT, headless React/ProseMirror), Lexical (MIT, React bindings, custom nodes/HTML integration), Quill (BSD-3-Clause, standalone editor). Choose Tiptap: matches the documented stack, React 19, shadcn controls, HTML mail and extension model. No existing rich editor dependency was installed. Only MIT core/StarterKit/Image/React/PM packages 3.31.4 are used; no paid extensions, cloud editor service, AI or collaboration.
- Add sanitize-html 2.18.0 + types: parsed server allowlist shared by composed HTML and signatures. Replaces a hand-built signature tokenizer that dropped images and double-escaped entities. DOMPurify remains the browser paste/initial-content sanitizer.
- jsdom 26.1.0 is test-only for editor/sanitizer integration and supports the repo's Node baseline. Existing happy-dom 15 returns an empty string for DOMPurify input containing scripts; no production workaround weakens sanitization. Other Web suites retain their environment.
- cloud-mail reference: mail-worker/src/service/attachment-upload-service.js stores files in R2; email-service.js partitions provider attachments and appends R2 download links to HTML/text. This project uses the existing bound R2 bucket through a streaming Worker endpoint, avoiding new S3 keys and bucket CORS setup. Files up to 64 MiB; PNG/JPEG/GIF/WebP images up to 5 MiB, checked by type and magic bytes. Browser sends raw Blob, not base64/JSON.
- Dedicated editor-assets module owns D1 metadata and usage relations, platform/editor-upload-store owns streaming R2/digest. Authorized mailbox send or signature.manage routes upload; random 256-bit recipient capability URLs serve only these intentional uploads. Existing inbound/private attachment authorization is unchanged. Downloads force attachment/octet-stream; raster images can render inline; nosniff, CSP sandbox, no-referrer, no-store.
- Metadata in migration 0029; raw bytes only in R2. Pending uploads expire in 7 days; D1 usages are inserted atomically with send/signature writes and FK-protect published assets. Published assets remain durable for historical mail even if a signature is later edited/deleted. Cron deletes expired unused uploads and sweeps orphan R2 objects with a cursor. Pending actor quota: 100 files / 256 MiB. Never log bytes, filename, token or capability URLs to audit.
- Brevo documents 20 MB for complete API mail including attachments. Hosted assets add URLs only; HTML cap 500,000 UTF-8 bytes. Existing binary attachment APIs remain supported with a conservative 18,000,000-byte estimate including base64/line wrapping and MIME allowance, validated at compose and provider adapter boundaries.
- Enabled domain signature is sanitized and appended on compose once before persistence, so provider retries do not append it again. Plain-text alternatives include uploaded URLs.
- /mailbox is default entry; /mailboxes is the explicit list. Default selection validates accessible active mailboxes: per-user last used, login address, owned mailbox, first available. No mailbox -> existing list empty state. No credentials in storage. Upper-left switcher always navigates to inbox, closes mobile navigation, works in collapsed sidebar and admin.
