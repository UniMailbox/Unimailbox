# CAP-A1 — Bind every access token to a D1 session

## Scope

Finish the application-owned Bearer authentication boundary already introduced in the working tree. A KV access-token entry containing only a user ID must never authenticate a request. Every accepted token must identify an unexpired, unrevoked D1 session belonging to an active user.

## Owned files

- `apps/worker/src/http/middleware/authn.ts`
- `apps/worker/src/http/routes/auth.worker.test.ts`
- `apps/worker/src/http/router.ts` (stale authentication comments only)
- Worker test fixtures in `apps/worker/src/http/routes/*.worker.test.ts` and `apps/worker/test/*.worker.test.ts` that manually seed cached access tokens
- `package.json` test commands (run Worker pool projects sequentially)
- `docs/rebuild/12-mail-system-implementation-plan.md`
- `docs/rebuild/capability-ledger.md`

## Acceptance

1. A token generated by login authenticates `/api/v1/auth/me`.
2. A cached token with no session ID is rejected, even when its user ID exists and is active.
3. A cached token bound to a revoked or mismatched D1 session is rejected while the KV entry still exists.
4. Cloudflare Access assertions and Better Auth cookies remain outside the runtime authentication path.
5. Existing Worker fixtures use D1-backed access tokens so the full Worker suite exercises the stricter rule instead of failing at login.
6. Unit and Worker scripts cover every configured Vitest project without launching multiple Worker pools together; full gates run and any remaining limits are reported precisely.

## Boundaries

Preserve unrelated uncommitted work. No remote deployment, schema change, login API shape change, or UI redesign in this slice. D1 remains the session and account-status authority; KV remains a short-lived token lookup.
