# Unimailbox 1.0.0

First stable source release of the rebuilt Cloudflare mail application.
This Release publishes source and upgrade instructions. It does not upgrade an
existing installation automatically or change its DNS or provider settings.

## Included behavior

- Administrator-created accounts, application-owned sessions, roles and explicit
  mailbox access. Administrators assign mailbox read/send/manage permissions;
  newly assigned mailboxes default to all supported mailbox permissions.
- Multi-domain mail through Cloudflare Email Routing and the Brevo outgoing
  adapter, rich compose, drafts, replies, scheduled sending, attachments, audit
  records, personal settings and English/Simplified Chinese.
- Administration editing in modals, single-column settings and user forms,
  searchable mailbox tags, bottom action groups and cancellation that discards
  unsaved role/signature changes. AI revision conflicts can be canceled.
- Optional AI reply assistance with Workers AI, Anthropic and OpenAI-compatible
  providers. External credentials are encrypted; AI is disabled by default.
  Inline model reasoning is excluded from generated email text.
- An administrator version panel with stable upstream Release/upgrade links.
  Checks use an anonymous fixed GitHub endpoint and bounded requests, with six-hour
  success/no-release caching and 15-minute failure caching. They require
  `settings.read`; `UPDATE_CHECK_ENABLED=false` disables external checks.
- Installation, independent fork upgrade and recovery guides, plus a verified-tag
  workflow that creates a draft for release-note review before publication.

## Installation and upgrade

Read the [installation guide](../operations/agent-deploy.md),
[update guide](../operations/updates.md) and
[release/recovery runbook](../operations/deploy.md).

The runtime requires Cloudflare Workers, D1, R2, KV, Queues, Secrets Store and a
custom HTTPS domain. Incoming mail requires Email Routing; outgoing mail requires
Brevo and verified senders. Use the pinned Node/pnpm toolchain and frozen lockfile.
The checked-in maintainer deployment configurations must be replaced or reviewed
for the operator's own account, domains and resources. VPS/Docker, POP3/IMAP and
SMTP-provider onboarding are not supplied by this release.

Rebuilt installations use ordered migrations `0001` through `0034`. Since the
previous upstream main snapshot, `0034_ai_configuration.sql` adds the optional
AI configuration table and setting. The canonical publication command applies
pending migrations and verifies their companions. Keep existing account/resource
identities and encryption keys. Back up D1 and R2, preserve the recovery bookmark,
and review fork changes before upgrading. Code rollback does not reverse schema
changes; never replace the encryption key to repair an upgrade.

The legacy application has a different migration history. Do not apply these
migrations to its database; use a fresh installation or a separately reviewed
data-import plan. Existing rebuilt installations do not repeat bootstrap or setup
during a routine upgrade. Complete real sign-in, mailbox grants, incoming,
outgoing, reply and attachment checks on each installation after upgrading.

## Verification and known limits

The release requires the full `pnpm verify` gate and matching tag/product version.
Dated [QA records](../qa/) distinguish local tests, synthetic browser observations,
exact-source staging publication and live provider/delivery evidence. Scheduled
send/cancellation and attachment-byte checks have real staging evidence; recent
administrator layout checks used local synthetic data. The comprehensive
[acceptance catalog](../qa/acceptance-test-cases.md) has not been executed as one
complete run. These records do not establish a new installation's acceptance.

The version panel provides notification and instructions, not automatic
deployment. GitHub subscription and email delivery depend on the operator's own
notification settings. Provider setup after initial setup has narrower UI
capabilities; use the documented supported flow rather than assuming all providers
can be provisioned from Administration. Existing-system imports and provider
expansion remain separate work. Hosted editor-upload links are recipient
capabilities; private incoming attachments retain authenticated access.

Dependency advisories remain open. The release audit reports one critical and
13 high findings, including the Happy DOM test environment, Vite development
server, tooling transitive dependencies and Seroval through the frontend router.
These were not upgraded in this release; exploitability has not been established
for the deployed application. See the
[release verification and dependency audit](../qa/release-1.0.0-2026-10-12.md)
for exact scope. Passing functional tests is not a security clearance.
