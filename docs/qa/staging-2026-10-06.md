## 本轮发现并修复

1. Hosted Web Crypto 拒绝 PBKDF2 超过 100,000 次；原 600,000 次导致管理员初始化 500。加入标准兼容 derivation 后，真实登录又触发 CPU 上限（1102，tail 为 exceededCpu）。用户明确批准降低密码强度后，新应用密码调整为 **100,000 次 PBKDF2-SHA256**，保留随机 16 字节 salt、256 位哈希及常量时间比较。只重设本轮创建的 staging 管理员测试哈希，并记录 operator audit。既有高迭代哈希仍按存储迭代数验证，其 CPU 需求需要合适的平台限额；没有批量修改旧用户。凭据 envelope 允许当前与旧两种成本。
2. Brevo 官方回调使用静态 Bearer 鉴权及 `message-id`、`ts_event` 字段。原代码只接受自定义 HMAC/camelCase，不能直接接入真实回调。已支持 Brevo Bearer、实际字段和事件别名，保留原 HMAC 兼容；鉴权失败在 JSON 处理之前被拒绝。[Brevo 安全 webhook 文档](https://developers.brevo.com/docs/secured-webhooks)、[实际 payload 文档](https://developers.brevo.com/docs/transactional-webhooks)。
3. 普通邮件标题原先只是文本，无法从列表打开已实现的详情路由。已添加 mailbox/message scoped 链接，19 个页面测试通过；移动端多行 inline 标题的中心点曾落在非链接空白处，已将链接设为 block，使整个标题区域可点击。最终部署包含该修复，并在 390px 浏览器中点击进入详情成功。
